## Why this matters

`npm audit --omit=dev` reports 10 vulnerabilities (6 high, 4 moderate) in the production dependency tree. The most significant: `path-to-regexp` ReDoS (high, via express → used for route matching), `qs` DoS (moderate, via body-parser → used for query parsing), `form-data` CRLF injection (via axios), and `hono` path traversal (high, transitive via `@modelcontextprotocol/sdk`). These are all reachable from the HTTP transport layer which processes untrusted network input.

## Steps

### Step 1: Run npm audit fix for safe automatic updates

Run `npm audit fix --omit=dev` to apply automatically fixable vulnerabilities. This will update `package-lock.json` with patched versions of transitive dependencies where semver allows.

```bash
npm audit fix --omit=dev
```

**Verify**: `npm audit --omit=dev 2>&1 | tail -5` → check if vulnerability count decreased. Note the remaining count.

### Step 2: Update express to latest 4.x patch

Express 4.x is the current major version in use. Update to the latest 4.x patch to fix the `path-to-regexp` and `qs` vulnerabilities:

```bash
npm install express@^4.21.0 --save
```

This pulls Express 4.21+ which depends on `path-to-regexp >=0.1.13` (patched for ReDoS) and `qs >=6.13.0` (patched for DoS).

**Do NOT upgrade to Express 5.x** in this plan. Express 5 has breaking changes (query parser defaults, removed methods, async route handler changes) that require code review. That's a separate future plan.

**Verify**: `npm audit --omit=dev 2>&1 | grep -i "path-to-regexp\|qs\|body-parser"` → no matches (these vulnerabilities should be resolved)

### Step 3: Update axios to latest 1.x patch

Axios 1.7.9 has the `form-data` CRLF injection vulnerability. Update to the latest 1.x:

```bash
npm install axios@^1.12.0 --save
```

This pulls a patched version of axios with updated `form-data`.

**Verify**: `npm audit --omit=dev 2>&1 | grep -i "form-data"` → no matches

### Step 4: Address hono vulnerability (MCP SDK transitive dep)

The `hono` vulnerability comes through `@modelcontextprotocol/sdk`. Check if a newer SDK version is available that updates the transitive dependency:

```bash
npm outdated @modelcontextprotocol/sdk
```

If a newer version is available (e.g., 1.30+), update:
```bash
npm install @modelcontextprotocol/sdk@latest --save
```

If the latest SDK version still depends on a vulnerable `hono`, use an npm override in `package.json`:

```json
  "overrides": {
    "hono": ">=4.12.25"
  }
```

Then run `npm install` to apply the override.

**Verify**: `npm audit --omit=dev 2>&1 | grep -i "hono"` → no matches, OR if the SDK can't be updated, confirm the override is in place and `npm ls hono` shows the overridden version.

### Step 5: Run full verification

**Verify**: `npm run typecheck && npm run build && npm test` → all exit 0

### Step 6: Check remaining audit status

**Verify**: `npm audit --omit=dev 2>&1 | tail -10` → should show 0 vulnerabilities, or only low/moderate ones that can't be auto-fixed (report any remaining)

## Maintenance notes

- **Express 5 migration**: This plan stays on Express 4.x. A future plan should evaluate Express 5, which has breaking changes: default query parser changed from extended to simple, `res.send(status)` removed, path route matching changes. The codebase uses `express.json()` and simple route handlers, so the migration should be straightforward but needs testing.
- **npm overrides**: If you added an `overrides` section for `hono`, it should be removed once `@modelcontextprotocol/sdk` updates its dependency. Check periodically.
- **Audit in CI**: After Plan 001 adds a CI `test` job, consider adding `npm audit --audit-level=high` as a CI step to catch new vulnerabilities automatically.
- A reviewer should run `npm audit --omit=dev` independently to confirm the vulnerability count is actually reduced.
